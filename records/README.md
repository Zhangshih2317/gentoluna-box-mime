# 记录、脱敏与复现

`evidence/` 包含本工作目录保存的JSON、JSONL和文本诊断记录。
成功、失败、只读预检和缓存计算全部保留，不只挑选成功日志。
超过1MB的文本记录以 `.gz` 存储，使用Python `gzip.open`或常见解压软件阅读。
没有将历史记录放回运行入口的新 `evidence/`，避免和新机器运行混淆。

## 索引

- `manifest.json`：原始相对文件名、导出文件、字节数、原始与脱敏后哈希。
- `run-index.json`：从事件日志提取的阶段数、完成事件、故障、退出状态。
- `summary.json`：两套已完成流程的关键指标。
- `public-packaging.patch`：现场实现与公开部署副本的代码差异。
- `publication-validation.txt`：公开版离线验证结果。

原始哈希用于对照本地档案。脱敏后哈希属于导出时版本；后续公开部署修改以Git和差异文件为准。
摘要不能替代完整日志，不能凭 `sdk_disconnected` 判断成功。

## 脱敏

用户主目录名替换为 `operator`；原现场三个地址替换为 `192.0.2.*`文档地址；
MAC、认证相关字段及运行标识按导出规则处理。关节角、比例、时间戳、错误类型和阶段顺序保留。
脱敏不是对每种潜在设备信息的形式化证明；发现遗漏可提交issue并移除敏感内容。

密码、SSH私钥、GitHub令牌和个人SSH连接器不进入仓库。
引用厂家SDK位置的文字与参数名用于诊断，不包含厂家源码副本或安装包。
厂家手册截图和音频素材不再分发。其余图片是否发布及排除原因在manifest中列出。

## 时间与版本

文件名由Windows主机当地时间生成；事件UTC来自机器人端，现场存在时钟偏差。
不要用两台机器的墙钟差计算通信时延。单次日志内 `elapsed_seconds` 和单调采样时间更适合分析。

这是2026-11-11至2026-11-13的工作目录快照，早期README与阶段报告可能描述尚未落地的方案。
读历史文档时同时看日期与最新 `docs/`。没有保存到工作目录的聊天附件或每次编辑版本，
不能在此虚构补齐。
