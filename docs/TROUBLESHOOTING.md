# 踩坑与处理索引

本页将“已经找到并修正的软件原因”“仅有证据的推断”“仍未确定的硬件行为”分开。
旧版本的精确代码并非每次都保留，不能凭当前源码反推所有旧执行细节。
记录文件名在 `records/evidence/`；大反馈文件增加 `.gz`。

## 证据阅读方法

先检查 `request` 确认预检/执行模式，再找 `stage_start` 和最后一个 `stage_complete`。
只看到 `sdk_disconnected` 不代表动作成功：应检查 `mime_complete` 或 `demo_complete`、
`remote_exit_code` 和 `completion_confirmed`。
六轮每个 `demo_cycle_complete` 只确认那一轮，最后 `demo_complete` 才确认整套。

出现错误时，同时查看同名 `-response.jsonl.gz`，不要只看异常栈最后一行。
主机文件名时间与机器人事件UTC存在时钟偏差，阶段耗时优先使用同一单调时钟。

## 普通等待不是硬故障豁免

2°是默认搬箱阶段的实际位置容差；它不修改机械限位、故障码、通信心跳或所有启动/恢复条件。
控制器仍有故障、反馈无效或硬界限超出时，代码仍可能进入异常和急停路径。
本次修正目标是减少普通跟随差异造成的误停，不是删除保护。
