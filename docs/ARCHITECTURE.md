# 结构、参数与算法

## 执行链

```text
Windows入口 / 手动 --execute
  → 本地配置 + SSH密钥
  → Linux环境脚本
  → 单进程独占锁 + 连接心跳
  → GentoRobot SDK + 实际反馈 / SG倍率回读
  → 预检 / 模型缓存 / 当前恢复段
  → 双臂原生Position + BODY协调位置流
  → 两次合格反馈 → 下一阶段 → HOME → 保持Position
```

单轮从 `tools/` 装载远端模块。六轮从 `demos/box_mime_six_cycles/` 装载独立快照，
避免后续单轮修改无意影响六轮；修复共同问题时应同时维护并分别测试两个版本。
两者共享示教点和本地深度求解工具，各自使用独立几何缓存。

## 参数

两个入口文件顶部各自配置，修改哪个入口就只影响哪个程序：

| 名称 | 归档成功值 | 作用 |
|---|---:|---|
| `ARM_SPEED_PERCENT` | 100 | ARM0/ARM1运行时速度比例 |
| `ARM_ACCELERATION_PERCENT` | 50 | ARM0/ARM1运行时加速度比例 |
| `BODY_SPEED_PERCENT` | 100 | BODY比例及协调时间预算 |
| `BODY_ACCELERATION_PERCENT` | 50 | BODY加速度比例及协调时间预算 |
| `HOME_SPEED_PERCENT` | 30 | 单独HOME入口的速度 |
| `HOME_ACCELERATION_PERCENT` | 10 | 单独HOME入口的加速度 |
| `SQUAT_DEPTH_CM` | 30 | 相对HOME的躯干下降量 |

百分比范围1～100。速度百分比、物理角速度、外部软件预算是不同量。
公开副本没有重新标定这些参数。跨设备复用先调整为适合本机的低速参数。
仅改比例不改变名义几何点位；改深度、点位、模型、远端模块源码则重建缓存。

## 下蹲几何

示教分支的30cm求解结果约为：

```text
ΔB2 = +57.547449683°
ΔB3 = -103.774089593°
ΔB4 = +46.226639909°
ΔB2 + ΔB3 + ΔB4 = 0
```

`mime_squat_height.py` 使用标定运动学，二分求下降深度，检查姿态、
下降单调性及水平通道。这个关系来源于本机示教，不能跨机构照搬。

BODY使用共同五次进度 `s(t)`：

```text
q_i(t) = q_i(0) + Δq_i · s(t)
s(u) = 10u³ - 15u⁴ + 6u⁵,  u=t/T
```

统一时长满足每轴速度、加速度、jerk约束：

```text
T >= max_i(
    1.875·|Δq_i|/V_i,
    sqrt((10/sqrt(3))·|Δq_i|/A_i),
    cbrt(60·|Δq_i|/J_i)
)
```

按50Hz向上取整。当前部分上限是软件预算，不是负载下电机实测极限。
共同进度维持目标角度和；实际跟随仍可能不同。没有启用固定延迟前馈。

## 双臂原生目标

`native_arm_motion.py` 对四个正式手臂阶段分别写完整目标并读取实际到位。
不用外部慢速曲线再逐点逼近完整目标。两臂及J3/J4内部进度可能不同，
因此缓存检查独立关节组合，不能只检查旧同步曲线。

SDK输入回显只说明命令接收；实际位置反馈才用于到位。
现场读取过逐轴 `VelMax=180°/s`，J1/J2 `AccMax=450°/s²`、其余900°/s²；
这些是该控制器配置，非公开版保证的负载性能。

## 全身到位与等待

`position_acceptance.py` 默认按各轴绝对误差不超过2°，
两个不同有效反馈帧相隔0.1～1秒确认；不合格重计数。
完整终点各轴已在2°内时，不再因误差和重复否决。
保持位也使用这一容差，但硬故障、无效值、速度边界等仍独立检查。

BODY普通偏差会冻结指令进度并保持最后目标，满足恢复条件后重规划剩余段。
这不是完全平滑的动力学刹停。正常完成保留Position；外层硬异常仍会请求急停。
独立HOME、启动检查、旧 `--stepped` 不应被描述成已全面套用新规则。

## 日志

事件日志用于阶段、模式、比例、故障和完成结果。
逐周期反馈用于实际/目标、回显、帧号、读取时间、进度、等待和异常分析。
六轮新增 `cycle_index` / `turn_relative_deg`，便于隔离某一轮。
公开记录的压缩仅改变存储形式，数字、顺序、时间戳未因脱敏而改写。
