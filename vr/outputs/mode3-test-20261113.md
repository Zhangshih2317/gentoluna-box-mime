# Apex 模式 3 单次切换测试

日期：2026-11-13。机器人日志时间与电脑约有 13 分钟偏差，以下事件时间采用机器人日志。

## 操作范围

退出 FXPlatform，确认 8760 网关和 Teleop 停止；仅启动 Robot。
用临时 systemd 配置加载诊断库，在原进程中观察 SDK 的 PD 调用，不新建 SDK 连接，也不修改传入参数或返回值。
诊断库使用本机 SDK 的 FXCommon.h 读取 RT；切换前双臂状态与外部 ROS 反馈一致，帧号递增。

原倍率 HTTP 接口返回服务不可用。随后临时启动 Robot，速度和加速度参数均为 5；启动日志和 ROS 参数读回均确认 5。Ready 成功，初始状态全部为 0。

仅调用一次 POST /api/v1/robot/mode，mode=3。未启动 Teleop，未发送关节目标、Home 或轨迹指令。

## 实测结果

| 对象 | SDK 返回 | 实时模块状态 | 模块错误码 |
| --- | --- | --- | --- |
| 左臂 obj=0 | -10 | 100 | 106 |
| 右臂 obj=1 | -10 | 100 | 106 |
| 躯干 obj=3 | 0 | SDK CurrentState=11，原始 RT cur=2 | 0 |

切换发生于机器人日志 11:21:52–11:21:55。本机 SDK 头文件定义：

- ERR_RequestTorqueMode = 106：请求力矩控制模式失败。
- FUNC_RET_OPERATION_TIMEOUT = -10：操作超过允许时间。

Apex 给三次 PD 调用传入的参数均为 timeout=1000、vel=100、acc=100，即没有沿用启动时设定的 5。这是倍率传递问题的直接证据，但不是错误 106 的已证实原因。

HTTP 提前返回 /control/set_mode 超时，SDK 调用仍继续执行右臂与躯干切换。一次 HTTP 超时不能视作底层操作已经取消。本次等待底层调用完成后才清理。

## 结论与未决项

已复现并定位至双臂请求力矩控制模式失败；当前不能仅凭错误码认定电机损坏、驱动版本不兼容、超时时长不足或未回 Home。
应核对双臂伺服对力矩控制的支持、控制器/SDK 配套关系、切换条件及控制器详细诊断。没有修改伺服模式映射、放宽保护或延长超时重试。
