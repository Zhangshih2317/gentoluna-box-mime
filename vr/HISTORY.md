## 遇到问题时先看哪一层

| 症状 | 怎样判断 | 对应处理 |
|---|---|---|
| PICO 连接不上 | `adb -d get-state`、`tun0`、Windows 到 `6.6.7.100` 的网卡和 9010 TCP 连接分开查。`8080` 能打开只代表 HTTP 通 | 头显确认调试与 VPN 授权，恢复有线地址与隧道，再进入头显 Apex 控制器模式 |
| Wi‑Fi 投屏消失，或怀疑视频绕无线 | 跟踪房间 10 的媒体 UDP 目的地址；PC 接收器测试与 PICO 原生测试分别计数 | 保留头显 Wi‑Fi 和 `/32` 路由，按[安装指南](README.md#3-恢复-1080p-彩色视频)针对当前无线地址复核临时过滤 |
| 有控制但无图 | 查所选节点是否支持彩色 1080p、是否被旧预览占用、ROS 本地图是否出帧、房间是否被 PC 占用 | 释放旧预览并选择实测彩色节点。PC 与 PICO 分别用 11、10 |
| 扳机数值在变，夹爪无动作 | 同时看 `/info/vr_connected`、`/control/enableL` 或 `R`、`/control/gripperValueL` 或 `R` 和 `apex-robot` 日志。检查已加载 SDK 和两个预检结果 | 启用 Tool、握侧握、松开再按。跟踪丢失会撤销侧握，TCP 可能仍连着 |
| 首次启动或重启遥操后不动 | 有无新租约、`passed read-only preflight`、`requested`、`acknowledged`；检查 `systemctl cat apex-robot apex-tool` 和 `/proc/<Robot节点PID>/maps` | 使用同一现场版 Robot/SDK。重进后重新建立输入边沿。独立手动程序只在已释放控制器时使用 |
| 左腕出错或突然停住 | `0x0418` 是普通位置读回；`0x0102` 是参数准备；`0x0108` 是动作指令。检查最后一条日志属于哪一步、是否收到完整有效回执 | 等待该侧 3 秒复查，出现恢复日志后松开再按。连续五轮失败时保存该侧日志，检查接线、供电及报警，处理后再重启 Tool |
| 有掉落报警 | `/info/wrist485_L/R` 保留原始报警 B 和故障 A。单独 `0x1000` 是本机已知掉落位 | 只对指定掉落位按现场规则处理，其他位及停止确认继续参与判断 |
| 报告“已闭合”与实物不符 | 写入回执说明驱动接收命令。真实位置 `0`/`9000`、速度、状态字和目视结果能区分实际到位、停在中途、遥测缺失 | 先区分 `requested`、`acknowledged` 与位置反馈，日志中缺帧处保留未知。现场样本不能给出普遍的抓取力或端到端延迟 |

## 档案范围

[夹爪现场事件](history/wrist-events.txt)保留服务时间及适配器消息。可搜索 `suspended`、`recovered on check` 和 `locked`，对齐同侧的扳机、回执与恢复事件。各阶段目录中的 `from-release.diff` 表示从最终版回看该轮第一方源码的差异。[发布构建记录](history/release-rebuild.txt)包括 5 项回归和定制库的逐字节复现结果。

[现场诊断索引](history/diagnostic-index.json)列出 VR 工作区的原始取证文件、大小及原始 SHA-256，可与所有者留存的原件核对。[公开测试记录](history/stages/)包含各阶段 CTest、实机只读结果及扳机采样。[视频与腕部取样](outputs/)保留可公开的数值和实验报告。历史交接里的临时路径对应当时工位。

所有者的本地原件包括 Windows 工具和旧安装包、速度审计、项目工作区、Orin 历次构建与抓包、已安装专用库、服务日志和三个项目会话的可见交互。现场照片、完整网络抓包、登录资料和第三方原始包只留在私有归档。软件再分发和使用条件以各上游项目为准。
