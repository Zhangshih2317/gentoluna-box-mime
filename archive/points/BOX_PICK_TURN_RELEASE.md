## 需求解释

按“蹲下 → 抱箱 → 站起 → 转腰 45° → 保持站立张开双臂”整理。
“仍箱子”暂按“松开使箱子掉落”理解，尚待用户确认；没有规划主动挥臂投掷。
左右方向尚未指定，45°默认解释为相对抱箱站稳姿态的腰关节增量，
不是把腰关节设为绝对 45°，也不是已验证的地面航向变化。

## 动作阶段

| 阶段 | 身体与双臂动作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0 准备 | 核对起始身体姿态、箱子位置、末端附件与释放区域；底盘保持固定 | 起始状态、限位、负载、空间与控制权均核实 |
| 1 下蹲接近 | 身体降低到可抱箱高度，双臂绕开箱体接近两侧或已确定的承托部位 | 身体到位，双臂与箱子保持预定接近间隙 |
| 2 抱紧承托 | 身体保持蹲姿，双臂协同接触；根据实际夹具建立承托或夹持 | 经验证的检测或现场确认箱子被可靠支撑；仅关节到位不足以证明抱稳 |
| 3 起身 | 身体与双臂协调抬起箱子，保持已确认的抓取相对位姿 | 身体到达经确认的站姿、箱子离地且无滑移 |
| 4 转腰 | 保持站立和抱持，腰部相对该阶段起点转指定方向 45° | 腰部到位、速度稳定，箱体和手臂整个扫掠区域无干涉 |
| 5 张臂释放 | 身体保持转腰后的站姿；双臂协调向外退出抓取位置，解除实际夹具约束 | 确认箱子已脱离工具，工具不钩挂或拖拽箱体 |
| 6 结束保持 | 保持站立及已转腰姿态，双臂停在经验证的张开位置 | 结束，不自动下蹲、不自动回 HOME 或转回原方向 |

阶段之间由到位、接触及脱离条件驱动，不能用固定延时假装已抱稳。
抱稳与释放等事件检查不能被原腕部演示的整段连续播放替代。
从阶段 3 完成起，禁止再次安排下蹲；阶段 5、6 的 BODY 目标保持一致。
运行中出现失联、滑移或控制错误时，终止阶段推进，按经验证的带载停止策略处理；
不能自动张臂、回 HOME、切 IDLE、解锁制动或直接断使能。

## 本次读到的工程依据

- `tools/dual_arm_five_moves.py` 目前只实现双臂腕部示例，且监测 BODY
  变化超过 0.3°即拒绝继续；不能直接拿来执行全身抱箱。
- `run_dual_arm_large.py` 当前速度选项为 60%，加速度为 5%。
  这是现有腕部程序设置，不作为新动作的速度默认值或验收依据。
- 本地 `reference/robot_frames/calibration_transforms/` 提供 BODY/HEAD 模型、
  轴映射及工具坐标。映射记录标明 SDK B1～B6 对应同编号身体关节，符号为 +1。
- 使用现有 `BodyHeadKinematics` 离线计算，模型零位下 B2、B3、B4
  轴向均约为世界 -Y，B6 约为世界 +Z。因此前者参与蹲起俯仰，
  后者是转腰候选轴；这不提供可执行蹲姿角度。
- 用历史 BODY `[-0.744,9.281,-17.364,5.456,-0.296,-1.653]` 计算，
  B6 世界轴向约为 `[0.04584,0.01814,0.99878]`，并非精确地面竖直轴。
  如要求地面航向准确变化 45°，需采用完整身体姿态约束求解及验证。
- 模型 B1 限位约为 ±11°，历史控制器反馈为 ±30°；
  模型 B4 为约 [-55°,110°]，历史反馈为 [-110°,55°]。
  必须核对来源、正负号和当前控制器参数，不得自行翻转符号或放宽限位。
- 坐标库记录过挂钩与电缸工具；当前实物是否仍为该工具尚未确认。
  若采用挂钩，张开双臂不一定能释放箱子，需要明确脱钩路径。
- 当前本地精简模型没有完整手臂碰撞网格、惯性和箱子模型，
  动态世界标定也标明尚未达到控制验收状态，不能据此声称完成碰撞或稳定性验证。

## 生成轨迹前仍需补齐

1. 箱子的长宽高、重量、初始位置/底面高度，以及实际末端工具和承托方式。
2. 向机器人自身左侧或右侧转腰，45°指腰关节相对增量还是地面航向变化。
3. 最后是松开掉落、放到同高度承接台，还是主动甩出；释放区位置和高度。
4. 已示教或经验证的身体站姿、蹲姿及抱箱双臂姿态。
5. 当前 BODY 限位及轴向核对、完整碰撞与负载模型、接触/脱离检测或人工检查方式。
